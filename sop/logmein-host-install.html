1.Purpose

This SOP defines the standard order of operations when an Umbrella Automation technician installs the LogMeIn host on a client PC or server. The order matters: the computer must carry its final name and the Umbrella backdoor account must exist before LogMeIn is installed, so the host registers in LogMeIn Central under the correct name and we are never locked out of a machine we are responsible for. The procedure also makes sure every machine we take on leaves our hands with Chrome installed and Windows fully patched, including optional driver updates.

2.Scope

Applies whenever an Umbrella technician performs the LogMeIn host install themselves — on-site, or remotely through a temporary session such as a client-run installer, a previous provider's remote tool, or a one-time screen share. It covers Windows workstations and Windows servers; server-specific cautions are called out where they apply.

It does not cover the client self-service flow, where the client runs Umbrella-Slim.exe from the LogMeIn Installer page and emails us Computer-Info.txt. That flow creates the backdoor account only; the technician then completes this SOP from section 4.4 onward once remote access is established.

3.Definitions

TermMeaning
LogMeIn hostThe LogMeIn agent installed on the client machine. Once installed it appears as a computer in LogMeIn Central and provides our standing remote access.
LogMeIn CentralOur LogMeIn management console, where hosts are organized into per-client groups and deployment installers are generated.
Backdoor accountThe local administrator account named umbrella, with a unique password that never expires. Our guaranteed way back into the machine regardless of the client's own accounts, domain state, or password changes.
Umbrella-Slim.exeThe Umbrella support helper. Run as administrator, it creates the umbrella backdoor account with a generated strong password and writes Computer-Info.txt to the Desktop (and emails it to IT when the relay is configured).
GateA step that must be complete before the next one is allowed to start. Gates are marked Gate in the procedure.

4.Procedure

Order of operations: rename and reboot → backdoor account → LogMeIn host → Chrome → Windows Updates → power settings → endpoint protection → tidy-up → verify and document. LogMeIn goes on as soon as the two gates are passed, so everything after it can be finished remotely if time on-site runs out.

4.1Before You Start

  1. Confirm the work is authorized and tied to a ticket: which client, which machine, who the primary user is, and that the client has approved a reboot (two or more for Windows Updates).
  2. Identify the machine: make/model, serial or service tag, Windows edition, and whether it is a workstation or a server.
  3. Confirm the client's computer naming convention and the exact name this machine should receive. If the client has no convention, use the Umbrella default for that client and record it in the client notes.
  4. Confirm which LogMeIn Central group (client folder) the host belongs in. Create the client group first if it does not exist.
  5. Have a secure place ready to record the backdoor password — the Umbrella password manager entry for this client. Never a ticket, email, chat, or text file.
Servers: treat a server as a change, not a setup. Confirm a maintenance window with the client before any rename or reboot. Do not rename a domain controller, or any server that hosts applications, databases, certificates, or shares that reference its hostname, without a separate plan — a rename on those breaks things. For an existing production server, skip section 4.2 entirely unless the rename has been planned and approved.

4.2Rename the Computer and Reboot Gate

LogMeIn registers the host under the computer name it sees at install time. Renaming afterward leaves a mismatched or stale entry in Central, so the final name must be in place and applied by a reboot before section 4.4.

Navigate toSettings›System›About›Rename this PC
  1. Enter the name from section 4.1 exactly as recorded (15 characters or fewer; letters, numbers, and hyphens only).
  2. If the machine is domain-joined, Windows will ask for domain credentials that are allowed to rename the computer object. Use the client's domain admin credentials, not the backdoor account.
  3. Restart now. Do not continue until the machine is back up and hostname in a Command Prompt shows the new name.

The Find Your Computer Name guide is the client-facing version of this check if you need to confirm a name with a user later.

4.3Create the Umbrella Backdoor Account Gate

The umbrella local administrator account must exist and be verified before LogMeIn is installed. LogMeIn gives us the connection; the backdoor account is what we sign in with once connected, and it is our recovery path if the client's accounts change, the machine leaves the domain, or a user's password is reset.

Preferred method — Umbrella-Slim.exe

  1. Download Umbrella-Slim.exe from the LogMeIn Installer page onto the machine (or transfer it over).
  2. Right-click and Run as administrator. Leave Generate a strong random password selected — every machine gets its own password; never reuse one across clients or machines.
  3. When the installer finishes, record the username and password from the finish page (or Computer-Info.txt) in the Umbrella password manager under the client, keyed by the new computer name.
  4. Delete Computer-Info.txt from the Desktop once the credentials are stored. It contains the password in plain text and must not be left on the client's machine.

Manual method

If the Slim installer cannot be used, create the account by hand in an elevated PowerShell, then set the password when prompted:

  1. net user umbrella * /add
  2. net localgroup Administrators umbrella /add
  3. Set-LocalUser -Name umbrella -PasswordNeverExpires $true

Verify before moving on

  1. net user umbrella — confirm Password expires: Never and Local Group Memberships: *Administrators.
  2. Sign in to the machine as umbrella once (switch user or sign out/in) to prove the stored password is correct. A backdoor that has never been tested is not a backdoor.
Never share the backdoor password with the client, and never send it by email. If the client needs local admin access of their own, create a separate account for them under the client's own access policy.

4.4Install the LogMeIn Host

  1. In LogMeIn Central, open the correct client group and choose Add Computer (deployment). Generate the installer or installation link for that group so the host lands in the right place automatically.
  2. Download and run the LogMeIn installer as administrator on the client machine. Accept the defaults unless the client group has specific host settings.
  3. When the install completes, refresh Central and confirm the host appears online, under the correct group, with the new computer name from section 4.2.
  4. Set the host description in Central to the primary user and location (for example Front desk — J. Doe) so the computer is identifiable without opening it.
  5. Connect to the host from Central once and sign in as umbrella. This is the end-to-end test: connection path plus backdoor credentials.
Previous provider's remote tool still installed? Once LogMeIn is confirmed working, remove leftover agents such as ScreenConnect so two remote-access tools are not competing on the machine. The PC Scripts page has Remove-ScreenConnect.ps1 for the common case.

4.5Install Google Chrome

  1. Download Chrome from google.com/chrome only. Do not use third-party download sites or bundled installers.
  2. Install for all users (the standard installer does this when run as administrator).
  3. Open Chrome once to confirm it launches, then close it. Do not sign the client into a Google account unless that is part of the ticket.
  4. Leave the default-browser decision to the client's own standard; do not change it unless asked.

4.6Windows Updates

Navigate toSettings›Windows Update›Advanced options
  1. Turn on Receive updates for other Microsoft products when you update Windows.
  2. Turn on Notify me when a restart is required to finish updating.
ThenWindows Update
  1. Pause updates, then immediately Resume updates. This refresh forces Windows Update to re-check instead of trusting a stale result.
  2. Click Check for updates. Install everything offered and restart when prompted.
  3. After each restart, check again. Repeat until You're up to date shows with nothing pending.
ThenWindows Update›Advanced options›Optional updates
  1. Expand Driver updates. Install all applicable driver updates, plus any other optional updates that apply to the machine.
  2. Restart if required, then check Windows Update one final time.
Shortcuts: on the PC Scripts page, Set-WindowsUpdateOptions.ps1 turns on both Advanced-options toggles, and Open-WindowsUpdate.ps1 does the pause / resume / check routine in one run.

4.7Power and Sleep Settings

A machine that sleeps or hibernates is a machine that is offline in LogMeIn — we cannot wake it, and the client cannot be helped until someone touches it. Every PC and laptop leaves this procedure configured so it stays reachable while it has power.

Navigate toSettings›System›Power & sleep

Desktop PCs

  1. Sleep when plugged in: Never. The Screen turn-off timeout can stay — a dark monitor does not affect LogMeIn.
  2. Open Additional power settings → Change plan settings → Change advanced power settings → Sleep → Hibernate after: Never.

Laptops

  1. Sleep when plugged in: Never. Hibernate after (plugged in): Never, via the same advanced power settings path as above.
  2. Choose what closing the lid does → Plugged in: Do nothing, so a closed lid on a docked or desk-bound laptop does not take it offline.
  3. On battery, leave the client's normal sleep and lid behavior in place — a laptop running on battery is not expected to be remotely reachable, and keeping it awake would just drain it. Tell the user that remote support requires the laptop to be plugged in.

All machines

  1. Network adapter: in Device Manager, open the wired and wireless adapters → Power Management tab → untick Allow the computer to turn off this device to save power. A sleeping NIC drops LogMeIn even when the PC itself is awake.
  2. Servers: confirm the High performance power plan (or the client's standard) and that sleep and hibernate are disabled, which is normally the default on Windows Server.
  3. Test it: leave the machine idle for longer than its previous sleep timeout (or at least 30 minutes) and confirm it is still online in LogMeIn Central. A setting you have not seen hold is not a setting you can rely on.

4.8Endpoint Protection

Confirm the machine is running the client's standard endpoint protection before you leave it. Check the client notes for which product applies:

  • SentinelOne clients: deploy the S1 agent using the client's site token and confirm the machine appears in the S1 console. The PC Scripts page has the silent-install command.
  • Malwarebytes clients: deploy with the silent installer from the PC Scripts page and confirm real-time protection is on.
  • Remove or disable any trial antivirus the OEM preloaded (McAfee, Norton, HP Wolf Security) so it does not fight the client's real product. Remove-HPWolfSecurity.ps1 covers the HP case.

4.9New-PC Tidy-Up (Workstations)

Recommended on any new or freshly imaged PC. Each item has a script and a manual click-path on the PC Scripts page.

  • Show all system-tray icons on the taskbar (Show-AllTrayIcons.ps1).
  • Stop Microsoft 365 Copilot launching at startup (Disable-Copilot-Startup.ps1).
  • Uninstall OEM bloatware and any trial software the client did not ask for.
  • Confirm the time zone and clock are correct and syncing.
  • Delete installers you downloaded (LogMeIn, Chrome, Slim) from Downloads or C:\IT once the install is verified.

4.10Verify and Document

  1. From LogMeIn Central, connect to the host one more time after the final restart and confirm it comes back online on its own.
  2. Confirm the host name in Central matches hostname on the machine and the host sits in the correct client group with a description set.
  3. Confirm the umbrella credentials are in the password manager, keyed by computer name, and that Computer-Info.txt is gone from the Desktop.
  4. Record in the ticket and the client's asset list: computer name, make/model, serial, Windows edition and version, primary user, LogMeIn group, endpoint protection product, and the date.
  5. Close the ticket.

5.Completion Checklist

  • Ticket, client, machine, primary user, and reboot approval confirmed
  • Computer name agreed per client convention; LogMeIn Central group identified or created
  • Gate: computer renamed and rebooted; hostname shows the new name
  • Gate: umbrella local admin created; password never expires; sign-in tested
  • Backdoor password stored in the password manager; Computer-Info.txt deleted from the Desktop
  • LogMeIn host installed from the client group's deployment; online in Central with correct name, group, and description
  • Connected via Central and signed in as umbrella successfully
  • Leftover remote-access agents from previous providers removed
  • Google Chrome installed from google.com/chrome and launched once
  • Windows Update Advanced-options toggles on; pause/resume refresh done; all updates installed; restarted until nothing pending
  • Optional updates checked; driver updates installed
  • Sleep and hibernate set to Never when plugged in; lid-close set to Do nothing (laptops); NIC power saving off
  • Idle test passed: machine still online in LogMeIn Central after sitting idle past its old sleep timeout
  • Client's standard endpoint protection installed and reporting; OEM trial AV removed
  • Tidy-up done; installers deleted; time zone correct
  • Host reconnects after final restart; ticket and asset list updated; ticket closed
