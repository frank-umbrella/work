1.Purpose

This SOP establishes the standard process for responding to a SentinelOne (S1) threat detection on a client PC. SentinelOne is effective at discovering threats, but its own mitigation status is not yet trusted as the final word on whether a machine is clean. For any significant threat, independent malware scans and verification are required once we have hands-on access to the machine.

Why this exists: in a recent incident, a threat was initially believed mitigated based on S1 status — but the affected PC had actually been offline in LogMeIn for several hours. An S1 console status is not proof the machine has been remediated. Verify on the machine itself.

2.Scope

This procedure applies to client Windows PCs where SentinelOne reports a significant threat: anything that executed or was active, ransomware or credential-theft indicators, repeated detections, threats of unknown origin, or any detection where the machine was offline or unreachable when S1 reported mitigation.

A single quarantined PUP or a known false positive does not require the full process — use judgment. When in doubt, run the full process.

3.Definitions

TermMeaning
SentinelOne (S1)The endpoint detection and response (EDR) agent deployed on client machines. Detects and attempts to mitigate threats automatically.
Mitigated (S1 status)SentinelOne's own claim that it killed, quarantined, or remediated a threat. Treated as a starting point, not a conclusion.
PUPPotentially Unwanted Program — adware, bundlers, and similar software that is unwanted but not always classed as malware.
SFCSystem File Checker (sfc /scannow) — the built-in Windows tool that verifies and repairs protected system files.
C:\ITThe standard local working folder on client PCs for our tools and scan results.

4.Procedure

4.1Confirm Access and Actual Machine State

  1. Review the S1 console: what was detected, when, what action S1 says it took, and whether the agent is currently online.
  2. Confirm the PC is actually online and reachable in LogMeIn before trusting any mitigation status. A machine that has been offline cannot have been remediated, regardless of what the console shows.
  3. Note the gap, if any, between the detection time and when we actually gained access to the machine.
  4. Regain access to the PC (LogMeIn, or on-site if necessary) before proceeding.

4.2Prepare the Scan Tools

  1. Check the root of the C:\ drive for an IT folder. If it does not already exist, create C:\IT.
  2. Download the required tools from their official websites:
ToolOfficial sourceUsed for
Malwarebytes (free/personal)malwarebytes.comFull malware scan
AdwCleanermalwarebytes.com/adwcleanerAdware, PUPs, browser-related threats
ESET Online Scannereset.com (Online Scanner)Deep second-opinion scan
  1. If downloading directly on the affected PC is not practical or advisable, download the tools on your own computer and use LogMeIn File Transfer to move them to the affected PC.
  2. Place all three utilities/installers in C:\IT.
  3. Run the programs from the local C:\IT folder — not from a mapped drive, Google Drive, or another network location.

4.3Check Task Manager for Suspicious Processes

Before running any cleanup tools or scans, look at what is actively running on the machine.

  1. Open Task Manager → Processes.
  2. Look for anything unfamiliar or suspicious, especially processes using unusually high CPU, memory, disk, or network — anything dominating system resources or behaving abnormally.
  3. Look for unfamiliar remote-access tools, command-line processes, scripts, unusually named executables, or programs that do not appear to belong on the computer.
  4. For anything questionable, use Open file location and check the executable's location and publisher when possible.
  5. Document anything suspicious before terminating or removing it, so there is a record of what was running.
Keep perspective: high resource usage alone does not mean a process is malicious. The goal here is to identify anything that deserves further investigation before we begin changing the system.

4.4Check Recently Installed Programs

  1. Press Windows key + R, enter appwiz.cpl.
  2. Sort the installed programs list by Installed On so the most recent installs are easy to identify.
  3. Look for unfamiliar, suspicious, or unexpected software — particularly anything installed around the time of the incident: unwanted applications, remote-access utilities, PUPs, or anything installed as part of the compromise.
  4. Document anything suspicious before removing it, so there is a record of what was found.

4.5Run Disk Cleanup Before Scanning

Clear temporary and discarded files first so scan time is not wasted on files that can simply be removed.

  1. Open Disk Cleanup and select the C:\ drive.
  2. Click Clean up system files, and select the C:\ drive again if prompted.
  3. Select the applicable temporary/system categories — temporary files, cached files, and other unnecessary files that can safely be removed.
  4. Run the cleanup and let it complete before starting the malware scans.
Shortcut: the PC Scripts page has Open-DiskCleanup.ps1 (with a -SystemFiles switch) that opens the elevated system-files view directly.

4.6Scan 1 — Malwarebytes (Free / Personal Edition)

  1. Install Malwarebytes and run a full scan.
  2. Review and address anything detected.
  3. Export/save the scan results to C:\IT with the date in the filename — e.g. Malwarebytes_2026-09-09.txt (see 4.13).
  4. Afterward, disable Malwarebytes from starting automatically with Windows, so the user is not repeatedly prompted about the trial ending.
Shortcut: the PC Scripts page has Disable-Malwarebytes-Startup.ps1 for the startup step, plus the manual click-path for the in-app toggle.

4.7Scan 2 — AdwCleaner

  1. Run AdwCleaner directly from C:\IT — it is a lightweight, portable Malwarebytes utility (no install) that targets adware, PUPs, browser-related threats, and similar items.
  2. Review and address anything detected.
  3. Save/export the scan results to C:\IT with the date in the filename — e.g. AdwCleaner_2026-09-09.txt.

4.8Scan 3 — ESET Online Scanner

ESET has produced the best results so far and has found threats the other tools missed, including items located in other user profiles.

  1. Run a Custom Scan and scan only the machine's physical drives.
  2. Exclude Google Drive, mapped/network drives, and other virtual drives — otherwise the scan can take several hours because of the amount of data stored in those locations.
  3. Review and address anything detected.
  4. Save/export the scan results to C:\IT with the date in the filename — e.g. ESET_2026-09-09.txt.
  5. When closing ESET Online Scanner, make sure “Delete application data on closing” is selected, so ESET removes its application data and does not remain on the PC after the scan.
If that option was missed: ESET's periodic-scan leftovers survive on the PC and re-run at startup. The PC Scripts page has Remove-ESETOnlineScanner.ps1 to clean them up.

4.9Run System File Checker

Once the malware scans are complete and any detected threats have been addressed, check for damaged or modified Windows system files:

  1. Open Command Prompt as Administrator.
  2. Run sfc /scannow and allow the scan to reach 100%.
  3. Review the result to determine whether Windows found and repaired any corrupted system files.
  4. Restart the computer if needed.

4.10Browser Extensions and Proxy Check

  1. Check both Google Chrome and Microsoft Edge for unfamiliar, suspicious, or malicious extensions. Remove any extension that is not recognized or approved.
  2. Check Internet Options / Windows proxy settings for any proxy configuration that should not be there.
  3. If a proxy has been manually configured and is not part of the client's normal setup, remove it and verify that internet connectivity works normally afterward.

4.11Review the User's Administrator Access

  1. Verify whether the affected user's Windows account is a member of the local Administrators group.
  2. If the user has administrator access, determine and document why they require it.
  3. If there is no legitimate business or application requirement, review and remove the local admin rights according to the client's normal access policies.

A compromised account with unnecessary administrative privileges can make an incident significantly worse. Limiting users to standard access wherever possible reduces what malicious software or an attacker can change on the machine.

4.12Run Windows Updates

Once the scans and security checks are complete, bring the computer fully up to date.

Navigate toSettings›Windows Update›Advanced options

Verify that the following are enabled (both are disabled by default on many systems):

  • Receive updates for other Microsoft products when you update Windows
  • Notify me when a restart is required to finish updating — so the user is properly notified when a restart is needed.
ThenWindows Update›Advanced options›Optional updates
  1. Check for and install all applicable driver updates.
  2. Install any other applicable optional Windows updates.
  3. Restart the computer when required.
  4. Keep checking Windows Update after each restart until no applicable updates remain.
If Windows Update seems stuck: pause updates, resume/unpause, then check for updates again. This often forces Windows Update to refresh and begin checking normally. The PC Scripts page has Set-WindowsUpdateOptions.ps1 for the two toggles and Open-WindowsUpdate.ps1 for the pause/resume/check routine.

4.13Scan Documentation

For every malware-remediation incident, the results from all three scanners must be saved to C:\IT with the date in each filename, so there is a record of what was found and when each scan was performed.

ToolFilename format
MalwarebytesMalwarebytes_YYYY-MM-DD.txt
AdwCleanerAdwCleaner_YYYY-MM-DD.txt
ESET Online ScannerESET_YYYY-MM-DD.txt

If multiple scans are performed on the same day, add an identifier or the time to the filename so previous results are not overwritten.

5.Completion Checklist

For any significant S1 threat, the incident is not closed until every step below is done. This provides a layer of verification beyond S1's own status, and a record of scan results, suspicious processes, recently installed software, configuration issues, permission problems, browser changes, system-file issues, and patching gaps that may have contributed to the incident.

  • S1 detection reviewed; detection time vs. machine-online time noted
  • PC confirmed online and access regained (LogMeIn or on-site)
  • C:\IT created or confirmed; tools downloaded from official sources and run locally
  • Task Manager reviewed; anything suspicious documented before removal
  • Recently installed programs reviewed in appwiz.cpl (sorted by Installed On)
  • Disk Cleanup + Clean up system files completed
  • Malwarebytes full scan run; findings addressed; results saved; auto-start disabled
  • AdwCleaner run; findings addressed; results saved
  • ESET custom scan run (physical drives only); findings addressed; results saved; application data deleted on close
  • sfc /scannow completed and result reviewed
  • Chrome and Edge extensions reviewed; unapproved extensions removed
  • Proxy settings verified clean; connectivity confirmed
  • User's local administrator access reviewed and documented (removed if unjustified)
  • Windows Update toggles verified; all updates including optional/driver updates installed; restarted as required
  • All three scan results in C:\IT with dated filenames
  • Machine verified fully updated and clean; incident closed
